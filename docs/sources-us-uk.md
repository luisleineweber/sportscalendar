# USA and UK sports-calendar sources

Checked 2026-09-21. Scope: first version includes major league season highlights, cup or playoff finals, and senior national championships. It does not include full match schedules. UK means England, Scotland, Wales, and Northern Ireland; UK-wide or cross-border events are separate where useful.

## Recommended first-version source set

The [implementation plan](national-catalog-plan.md) defines the final update and selection rules. These source notes describe available data. Import only the agreed event kinds, even if a source also lists rounds or match dates.

## What this means for national detail

Two more shared-source leads were checked: [UEFA's 2026 competition calendar](https://www.uefa.com/news-media/news/02a0-1f71bdf70a9a-b6067bd647f2-1000--2026-european-football-calendar-match-and-draw-dates-for-a/) lists senior finals in HTML, alongside out-of-scope draws and youth fixtures. [ITF's Grand Slam page](https://www.itftennis.com/en/tours/grand-slam-tournaments/) identifies the four event owners. Use the ITF page for owner discovery; exact annual dates need those owners' event pages.

For the USA, the first release should contain major league season records (NFL, NBA, and MLB), the U.S. Open Cup final, and senior federation championships such as USA Cycling or USA Swimming. Each chosen league has separate opener and title-deciding closing records. Add a separate cup final or championship event when its date is confirmed. Do not import every game.

For the UK, use one GB country filter with home-nation detail: England (Premier League and FA competitions), Scotland (Scottish Cup and top-flight season), Wales (dated men's and women's Welsh Cup finals), and Northern Ireland (Irish Cup and Women’s Challenge Cup). Add Aquatics GB and UK Athletics as UK-wide championships. This gives small national events without pretending that one “UK calendar” owns all four football systems.

## Monthly refresh design

The source pages do not offer one dependable public API. The static site should therefore keep a small structured seed per source with:

Source registry: `id`, `urls_by_year`, `language`, `format` (`html` or `pdf`), `mode` (`parsed` or `reviewed`), `adapter`, `competition_keys`, `required_catalog_ids`, and `authority`. Reviewed event records keep identity, stage, dates, source URL, content hash, date-check time, and audience proof. See [the catalog process](catalog-process.md).

The monthly script should fetch each source page, extract only configured event types, normalise dates, and write a review report before replacing the catalog. Every source importer is a candidate until a parser has been tested against a saved fixture. It should fail the build when a date is missing, an end date precedes a start date, or a final date conflicts with an equal-priority source. For dynamic pages, save the raw HTML or PDF hash and show a “changed source” warning; do not silently publish an empty catalog.

Use automatic extraction for clear date tables and PDFs only after parser tests pass. Use a reviewed seed for FAW, UK Athletics, USA Cycling, USA Swimming, and other pages whose annual dates appear in news articles. Store the source URL with every event so a user can inspect the decision. Wikipedia may help discover a competition, but it should not decide country relevance or be the refresh authority.

## Limits and uncertainty

League schedules are often revised for television, cup progress, venue issues, or broadcast rights. The catalog should describe all-day date ranges and retain its `date_checked_at` evidence in the report. A monthly run can keep the data reasonably current, but it cannot promise live rescheduling.

The USA and UK federation pages vary in structure and may expose dates only after a draw or host announcement. The first version should publish only named finals, championship windows, and season highlights with confirmed dates. Provisional dates stay in the review report until confirmed. Full match schedules remain out of scope.
